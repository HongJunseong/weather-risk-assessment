# 로컬 커밋

완료된 저장소 작업은 사용자에게 다시 묻지 않고 로컬 커밋한다. 원격 변경은 별도 요청이
있을 때만 수행한다.

## 메시지

제목은 `<type>(<scope>): <한국어 요약>` 형식이며 scope가 불필요하면 생략한다.
type과 scope는 영문 소문자, 요약은 72자 이내로 쓰고 마침표를 붙이지 않는다.

| type | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 잘못된 동작·데이터 수정 |
| `refactor` | 동작을 유지하는 구조 개선 |
| `perf` | 성능·자원 사용 개선 |
| `test` | 테스트만 변경 |
| `docs` | 문서만 변경 |
| `build` | 의존성·패키징·Docker 빌드 |
| `ci` | CI 워크플로 |
| `chore` | 저장소 관리 |
| `revert` | 이전 커밋 되돌리기 |

주목적에 맞는 type을 선택한다. scope는 `dag`, `collector`, `bronze`, `silver`, `gold`,
`risk`, `alert`, `docker`, `ci`처럼 실제 중심 영역을 쓴다. 제목만으로 부족할 때만 빈 줄
뒤에 변경 이유, 영향, 주의사항을 한국어 본문으로 적는다. 필요하면 `Refs #123` 또는
`Closes #123`을 마지막에 추가한다. 호환성을 깨면 type 뒤에 `!`를 붙이고
`BREAKING CHANGE: <설명>`을 작성한다.

## 분리와 절차

- 한 커밋에는 독립적으로 설명하고 되돌릴 수 있는 목적 하나만 담는다.
- 기능과 직접 검증하는 테스트·짧은 문서는 함께 둔다.
- 독립적인 리팩터링, CI, 빌드, 문서 정리는 별도 커밋으로 나눈다.
- `git status --short`와 diff로 기존 변경을 구분하고 관련 검증을 실행한다.
- 파일을 명시해 스테이징한다. `git add .`과 `git add -A`는 사용하지 않는다.
- `git diff --cached --check`와 staged diff를 검토해 `.env`, 인증정보, 생성 데이터,
  무관한 변경이 없는지 확인한다.
- staged 변경 전체를 제목 하나로 설명할 수 있고, 되돌릴 때 목적 하나만 취소되는 경우에만
  커밋한다. 안전하게 분리할 수 없으면 커밋하지 않고 이유를 보고한다.
- 완료 후 커밋 hash와 제목, 검증 결과, 남은 변경을 보고한다.
